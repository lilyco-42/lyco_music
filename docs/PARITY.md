# lx-music 功能对齐清单（超集目标）

> 目标：**Lyco Music 必须是 lx-music 的功能超集** —— lx 能做的，我们都能做；lx 没有的（账号、会员、好友、云同步开箱即用），是我们的增量。

## 基准与判定方法

| 项 | 值 |
|---|---|
| 基准 A | `lx-music-desktop` **v2.12.6**（本地源码 `/d/demo/lx-music/lx-music-desktop`） |
| 基准 B | `lx-music-mobile` **v1.9.1**（本地源码 `/d/demo/lx-music/lx-music-mobile`） |
| 对照 | Lyco Music **0.2.26** |
| 判定依据 | 逐个读取 lx 的 `src/renderer/views/`、`src/renderer/views/Setting/components/`、`src/lang/zh-cn.json`（**316 个 `setting__*` 键**）、`src/main/modules/openApi/`、`src/renderer/core/useApp/useDeeplink/` |
| 统计口径 | 只统计**用户可感知的能力**，不把「一个设置项拆成多个」重复计数 |

图例：`已` = 已对齐；`部分` = 有但不完整；`缺` = 完全没有；`独有` = 我们比 lx 多出来的。

### 下载模块的两处「照搬会出事」的地方

1. **`.part` + rename 不能省。** 直接写目标文件，断电后磁盘上是一个后缀正常、
   内容残缺的文件 —— 用户点开放不了，而且下次下载的「同名跳过」会把它当成已完成。
2. **续传位置要信磁盘，不能信进度值。** `.part` 只顺序追加，永远是连续前缀；
   而进度值含还压在 WriteStream 缓冲里没落盘的那一截。按进度值追加，文件中间会留空洞。
   （lx 的 `worker/download` 用 worker 内部维护 offset，天然没这个问题；搬到主进程后必须显式处理。）

### 本地音乐的三处「不用自定义协议会出事」的地方

1. **`file://` 不能用来播本地文件。** dev 模式页面在 `http://localhost:5173`，Chromium 会把
   `file://` 子资源当跨源拦掉；生产模式页面本身就是 `file://`，反而能放。直接用它就会变成
   「打包后能播、dev 里不能播」这种最难查的怪现象。所以统一走 `lxmn-media://`。
   `registerSchemesAsPrivileged` 必须在 `app.whenReady()` **之前**调用，`standard: false`
   （standard 会规范化 URL 把路径改坏）、`stream: true`（否则整份下载完才开播）。
2. **Range 必须自己实现。** Chromium 媒体栈靠 `206` + `Content-Range` 跳进度条；返回 `200`
   整份文件也能播，但拖动会失效而且**不报错**。实测（2026-10-21，`Jux - Don't Say.mp3`）：
   `duration 218.78s`、`currentTime = 30` 能跳到、`play()` 后 0.7s 内 `currentTime` 前进
   `30 → 30.64`，说明 206 与解码链路都通。
3. **`.ncm` 是 DRM，不做解密。** 网易云自己的
   `VipSongsDownload\拷贝后其他播放器不可播放的解决方案.txt` 就是官方说明。扫描结果里要
   **如实统计并解释**跳过了多少个加密文件，否则用户以为漏导了。

## 两个必须提前说清的判断

**1. 1.2 自定义源脚本是分水岭。** 其余 67 项加起来，都不如这一项对「lx 老用户迁移」的影响大。lx 用户手里的源脚本是资产，不兼容就是让他们二选一。建议提到批次 1 一起做。

**2. 内置音源 + 商业化，风险高于 lx。** lx 正是因为腾讯投诉在 v2.6.0 移除了内置源，并在协议里写明「不接受任何商业合作及捐赠」。我们内置可用源 + 88 元年费，是把 lx 主动规避的那部分风险接了过来。这是产品决策，不是技术问题 —— 在台湾市场做没问题，但往大陆推的时候要重新评估。
